# 엑스툴 자동화 · 선수용 접수페이지

기준일: 2026-11-01 (한국 시간)

## 현재 운영 기준
- 접수페이지: https://dizfactree.github.io/marathon-qr/
- 이 저장소 루트의 index.html, style.css, app.js, codec.js와 assets/, vendor/가 현재 운영 코드입니다.
- marathon-qr-upload/는 이전 업로드 묶음입니다. 현재 운영 코드와 섞어서 덮어쓰지 마세요.
- 기존 ChatGPT Sites 주소는 과거 작업 이력입니다. 현재 운영 기준 주소는 위 GitHub Pages입니다.

## 확정된 동작
- 휴대폰에서 이름과 완주 기록 입력 → 숫자 QR 생성 → 수정 또는 PNG 이미지 저장.
- 입력 정보는 서버에 전송·저장하지 않고 브라우저에서 처리합니다.
- 이름은 NFC 정규화 및 앞뒤 공백 제거 후 코드포인트 기준 1~24자입니다.
- 한글·영문·숫자·공백 및 일반 문장부호/기호를 허용합니다.
- 그림 이모지, 이모지 조합, 이름 중간의 줄바꿈·제어문자를 제한합니다. 공백 정리 과정에서 앞뒤 줄바꿈은 제거됩니다.
- 일반 특수문자 허용으로 범위를 넓혔습니다. 과거의 좁은 허용 목록이나 “모든 이모지 지원” 설명은 현재 정책이 아닙니다.
- 기록 형식은 HH:MM:SS. 시간 00~99, 분·초 00~59이며 00:00:00은 허용하지 않습니다.
- 상단 이미지는 가로 전체와 원본 비율을 유지합니다. 모바일 입력 영역은 여백과 중복 문구를 줄였습니다.
- 상단 이미지는 461,598바이트 PNG에서 107,677바이트 JPEG로 변경했습니다.
- 작은 화면, 확대 글자, 키보드 표시 상태에서는 스크롤이 필요할 수 있습니다.

## QR 데이터 규약 v1
숫자로만 구성합니다.
1. 접두어 21801 (5자리)
2. 이름 코드포인트 개수 (2자리)
3. 기록 HHMMSS (6자리)
4. 이름의 각 유니코드 코드포인트 (문자당 7자리, 0 채움)
5. 위 본문을 97로 나눈 나머지 (2자리, 0 채움)

전체 길이는 15 + 이름 코드포인트 개수 × 7입니다.
QR 생성 시 encode/decode 왕복 결과를 대조합니다.
검사값은 오입력 탐지용이며 암호화·인증 기능이 아닙니다.

## 확인 수준
- 배포 사이트에서 이름·기록 입력, 일반 특수문자, 실시간 오류 안내, QR 생성·수정 화면을 확인했습니다.
- 코드 수준에서 일반 기호 왕복과 그림 이모지/제어문자 차단을 검사했습니다.
- 사용자가 별도 PC의 xTool에서 일반 특수문자 입력을 확인했습니다.
- 현재 웹 QR → 실제 스캐너 → 현재 각인매니저 → xTool → 실제 각인의 전체 연동은 이번 작업에서 아직 재검증하지 않았습니다.
- 각인매니저의 현재 소스·실행 파일은 이 저장소에 포함되지 않았습니다.
- 현장 다수 휴대폰의 접속 시간이나 동시 접속 성능을 실측한 것은 아닙니다.

## 복구 이력
이 웹 코드는 과거 원본 전체를 그대로 복사한 것이 아니라, 당시 확보한 HTML 및 규약 기록에서 복구·재구현한 코드입니다.
브라우저 내부의 QR 왕복 성공은 기존 각인매니저와의 호환성을 보장하지 않으므로 실제 수신 프로그램과 대조해야 합니다.

## 운영 원칙
- 접수페이지와 수신 프로그램이 같은 QR 규약을 사용하도록 유지합니다.
- 실제 각인 시작은 장비·작업자 환경에서 별도 검증합니다.
- 별도 도메인 연결은 진행하지 않았습니다.
- 화면/이미지 최적화와 서버 성능·통신망 문제를 구분합니다. 비용 지출이나 호스팅 변경은 실측 뒤 판단합니다.
